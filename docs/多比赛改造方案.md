# 多比赛改造方案（站点侧 + 裁判侧）

> 背景：农场对抗赛只是众多比赛之一，后面还要上线别的比赛。当前实现里「一个比赛」是写死的，
> 这份方案把它变成「多个比赛」的一等维度，并且保证农场对抗赛与历史数据平滑迁移。

## 一、现状：写死在哪几个地方

| 位置 | 现状 |
|---|---|
| D1 表 | `arena_matches`、`arena_replays` —— 没有「比赛」这一维，所有记录默认属于同一个比赛 |
| 接口 | `GET/POST /api/arena/matches`、`GET/POST/GET:id/DELETE /api/arena/replays` |
| 页面 | `/arena`（ArenaPage.jsx：登记战绩 + 积分榜 + 对战记录 + 回放列表） |
| 导航 | 顶部「对抗赛」 |
| 裁判侧 | `F:\AIkaggle对抗赛` 整个仓库就是农场对抗赛：`engine/rules.py` 是这一个比赛的规则、`config/format.json` 是它的赛制 |

## 二、目标

同一个站点承载多个比赛；每个比赛有自己的规则、参赛方、战绩与回放；
农场对抗赛作为第一个比赛平滑迁移，**历史数据一条不丢、旧链接继续可用**。

## 三、站点侧改造（三步，每步都能单独上线）

### 第 1 步：加「比赛」维度（只加表、加列，不动页面）

```sql
CREATE TABLE IF NOT EXISTS competitions (
  id          TEXT PRIMARY KEY,          -- 内部编号
  slug        TEXT NOT NULL,             -- 对外短名，如 kaggriculture
  name        TEXT NOT NULL,             -- 「农场对抗赛」
  subtitle    TEXT NOT NULL DEFAULT '',  -- 一句话说明
  rules_url   TEXT NOT NULL DEFAULT '',  -- 规则文档地址
  engine_sha  TEXT NOT NULL DEFAULT '',  -- 裁判引擎校验值（用于核验）
  score_model TEXT NOT NULL DEFAULT '1v1_cash',  -- 评分模型：1v1_cash / weighted_rank / ...
  status      TEXT NOT NULL DEFAULT 'live',      -- live / soon / archived
  sort        INTEGER NOT NULL DEFAULT 0,
  created_at  TEXT NOT NULL,
  deleted_at  TEXT
);
CREATE UNIQUE INDEX IF NOT EXISTS idx_comp_slug ON competitions(slug);
ALTER TABLE arena_matches  ADD COLUMN competition_id TEXT NOT NULL DEFAULT 'kaggriculture';
ALTER TABLE arena_replays  ADD COLUMN competition_id TEXT NOT NULL DEFAULT 'kaggriculture';
```

要点：
- D1 的 `ALTER TABLE ADD COLUMN` 不是幂等的，`ensureSchema.ts` 里要先查 `PRAGMA table_info` 再决定是否加；
- 同时把 `SCHEMA_VERSION` 提升（v3.13 → v3.14）触发迁移；
- 迁移后写入种子行：农场对抗赛 `slug = kaggriculture`，字段填上引擎校验值与规则文档地址。

### 第 2 步：接口加比赛参数

| 接口 | 变化 |
|---|---|
| `GET /api/competitions` | 新增：比赛列表（含每个比赛的场次数、最近一场时间） |
| `GET /api/arena/matches` | 加可选 `?competition=<slug>`，缺省 = 农场对抗赛（旧链接行为不变） |
| `POST /api/arena/matches` | body 内可带 `competition`，缺省同上 |
| `GET/POST/DELETE /api/arena/replays` | 同上；R2 对象键仍为 `replays/<id>.json`，**不迁移已有对象** |
| 写权限 | 维持现状：战绩与回放只有站长（upload/delete），删除另有管理员路径与审计日志 |

### 第 3 步：页面

- 顶部导航「对抗赛」→「比赛」；
- `/arena` 改成**比赛列表**：卡片显示名称、状态、参赛方、场次数、最近一次时间、「看榜单」；
- `/arena/:slug` 是单个比赛的积分榜 + 对战记录 + 回放列表（现有 ArenaPage 逻辑搬过来，加一个比赛参数）；
- `/replay` 播放器不变，按回放编号取数据。

## 四、裁判侧改造

```
competitions/
  kaggriculture/     规则（FORMAT.md）、引擎、config/format.json、种子集、回放格式版本
  <下一个比赛>/       同上，互不影响
```

- `scripts/run_league.py` 等加 `--competition`；
- **评分模型按比赛可插拔**：对抗赛是「1v1 胜负 + 终局现金」；算法测试那种是「多参赛方加权分排名」；
- 每次比赛都冻结提交并记录引擎校验值，站点 `competitions.engine_sha` 与之一致，便于第三方核验。

## 五、兼容与风险

- 迁移是**加法 + 默认值**：不删列、不改旧行，旧数据自动归到农场对抗赛；
- 旧接口、旧播放链接（`/replay#src=/api/arena/replays/<id>`）继续可用；
- R2 里的回放对象不搬家；
- 破坏性操作仍限站长/管理员，且写审计日志。

## 六、验收标准（实施时按这个测）

1. 迁移后 `GET /api/arena/matches` 返回与迁移前**完全相同的记录**（同一批 id、同样的排序）；
2. `GET /api/competitions` 至少返回「农场对抗赛」，带场次数；
3. 新建第二个比赛后，两个比赛的战绩、榜单、回放**互不串数据**；
4. e2e 沿用现有权限断言（写=站长），新增「跨比赛隔离」「缺省比赛兼容」两条；
5. 线上验证：`/arena` 列表可打开，`/arena/kaggriculture` 的榜单与改造前一致。

## 七、需要先定的三件事

1. **形态**：多个比赛走同一套页面（推荐：加比赛维度），还是每个比赛独立页面/子域名？
2. **评分模型**：各比赛是否都不同（1v1 胜负 / 多参赛方加权分 / 多轮淘汰）？这决定成绩表是「对局表」还是「成绩表」，或两张都要。
3. **时机**：现在就做站点侧改造（只加表加列 + 列表页，可先不接第二个比赛），还是等第二个比赛的需求明确后一起做？
