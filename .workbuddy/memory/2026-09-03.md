## 通读「AI vs 洛谷」全站代码（只读，未修改任何文件）

项目：Cloudflare Pages + Pages Functions + D1(SQLite)，多 AI 模型在洛谷题目上的解题能力对比站，v3.6。

### 架构
- `functions/api/[[route]].ts`（4 行）→ `worker/router.ts`（579）声明式路由表 + CSRF 双提交 + 进程内滑动窗口限流 + 请求体分级限额。
- `worker/store.ts`（649）权威数据层；`auth.ts`（347）PBKDF2-SHA256(100k) + HMAC 会话 + 每次请求回查用户表（password_version 使旧令牌失效）；`util.ts`（260）白名单清洗；`luogu.ts`（187）抓取（host 编译期白名单 + https + 题号正则 + 302 location 复校，manual 接 Cookie）；`schema.ts` 内联建表（Pages 不支持 [[rules]]，必须和 db/schema.sql 同步）。
- `ensureSchema.ts` 每 isolate 跑一次，用 PRAGMA 探测做增量 ALTER（v3.1 prompt / v3.2 nickname+审计字段 / v3.3 password_version / v3.5 deleted_at）。

### 核心业务口径（改代码前必须确认）
1. **收录制**：记录只在「题目在 problems 目录 且 模型在 models 目录」且 status=approved 时才可见；单处实现在 `store.ts: isRecordVisible`。
2. **三区数据**：显示区 / 隐藏区（已审核但未收录）/ 回收站（deleted_at 非空，软删除）。`POST /api/records/bulk {action:'reject'}` 是入回收站，不是物理删。
3. **聚合主键 = model**（variant/agent 仅展示）；**score=null 的轮次不计入任何均分、不按 0 计**。
4. **题目信息单一来源**：题名/难度由 problems 目录带入并锁死，测评表单不可改。
5. revision 单调递增（乐观并发），所有写操作 bump 它。
